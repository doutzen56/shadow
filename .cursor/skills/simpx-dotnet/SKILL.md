# SimpX .NET 实现技能

## 适用场景

- 需要进行 .NET 后端改动时。
- 需要保证实现符合项目现有风格和注释规范时。
- 需要输出可交付的实现步骤和断言清单时。

## 前置输入

- 需求目标与验收标准。
- 架构边界结论（`@@BA` 输出）。
- 相关代码路径与依赖组件。

## 执行步骤

1. 按边界拆分改动范围，避免无收益扩改。
2. 识别主链路、失败路径、幂等与重试点。
3. 先抽象可复用能力（能力模式、契约、状态机、策略点）。
4. 再落项目适配层（参数映射、依赖注入、配置绑定）。
5. 产出实现步骤和改动清单。
6. 定义断言清单（验证项、期望值、失败判定条件）。
7. 检查注释规范（XML 注释和业务注释）是否满足要求。

## 输出格式

- 抽象层说明（能力/契约/状态机/策略点）
- 实现步骤
- 变更模块清单
- 异常路径与兼容说明
- 断言清单

## 失败与升级

- 边界不清或断言无法定义时，升级 `@@BA`/`@@TL`。
- 发现高风险兼容问题时，标记阻塞并请求决策。

## 禁止事项

- 不绕过架构边界直接编码。
- 不省略失败路径验证口径。
- 不把业务代码大段复制为“可复用资产”，必须先抽象后适配。
