# SimpX 断言验证技能

## 适用场景

- 代码改动后需要进行测试环境交付验证。
- 需要把“期望值 vs 实际值”做成可复验报告。
- 需要验证 DB、Redis、MQ 与业务链路一致性时。
- 断言或场景需要打开页面、点控件、核对界面结果时（默认自动：先 Playwright，不可用再 Browser）。

## 前置输入

- 目标环境（取项目 `envs.yaml` 的 `default_envs` 中的一个，例如 hx-matching 的 `dev`/`uat`、betwin 的 `test`）。
- 环境配置来源；项目内置配置优先，只有用户或项目档案明确要求时才读取本地 `envs.secrets.yaml`。
- `@@BE` / `@@FE` 断言清单（验证项、期望值、失败判定条件）；含页面项时标出页面 URL 或入口。
- `@@BE` / `@@FE` 自验证结果；没有时先阻塞或要求说明原因。
- `@@TL` 验收口径和 `@@BA` 风险结论；重要需求据此补充真实业务场景。
- 有页面验证时：`@@DEVOPS` 或项目档案给出的可打开地址与登录方式。

## 执行步骤

1. 识别项目内置配置、默认环境和可用验证命令；判断断言清单里哪些项必须走页面。
2. 执行基础组件验证（DB、Redis、ES、MQ）。
3. 有页面项时，按固定顺序自动调用：① 先调已启用的 Playwright 插件 / Playwright MCP；② 仅当 Playwright 未安装、未启用或调用失败时，再调 Cursor 内置 Browser；③ 两者都失败则本项记「验证阻塞」。打开目标页，按断言步骤操作，记录实际用的是哪一步、页面结果与截图类证据。不要求用户再说「用 Playwright」。
4. 按断言清单执行其余业务验证（接口、库、缓存等），记录实际值。
5. 重要需求补充 3-7 个真实业务场景，并记录前置数据、操作步骤、期望状态、实际证据和清理方式；含页面的场景走步骤 3。
6. 收集证据（日志、查询结果、接口响应、页面截图/文案）；敏感字段脱敏。
7. 输出断言比对报告和场景验证结果（通过/失败/阻塞）。

## 输出格式

- 环境准备结果
- 页面验证工具与结果（只能是其一：已用 Playwright / Playwright 不可用已改用 Browser / 两者皆不可用故阻塞；须写明原因）
- 断言比对表（验证项/期望值/实际值/结论/证据）
- 风险与回滚建议

## 失败与升级

- 断言不清晰时先阻塞，回退给 `@@BE` / `@@FE` 重新定义。
- `@@BE` / `@@FE` 未自验证时先回退，除非无法自验证且已说明原因。
- 浏览器工具未启用或无法登录目标页时写「验证阻塞」，回流补环境或说明，不冒充通过。
- 验证失败时先回流 `@@BE` / `@@FE` 定位和修复；如果暴露边界、方案或验收口径问题，再升级 `@@BA` 或 `@@TL`。
- 关键断言失败时升级 `@@TL` 决策是否回滚。

## 禁止事项

- 不只做连通性，不做断言比对。
- 不输出无证据的“通过结论”。
- 有页面断言却不按「先 Playwright、再 Browser」调用，只写建议手工点。
- 未说明实际用了 Playwright 还是 Browser，或把二者写成可任选。
- 资金、订单、权限、登录等场景只用截图、不做约定的后端状态核对。
