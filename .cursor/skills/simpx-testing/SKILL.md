# SimpX 断言验证技能

## 适用场景

- 代码改动后需要进行测试环境交付验证。
- 需要把“期望值 vs 实际值”做成可复验报告。
- 需要验证 DB、Redis、MQ 与业务链路一致性时。

## 前置输入

- 目标环境（取项目 `envs.yaml` 的 `default_envs` 中的一个，例如 hx-matching 的 `dev`/`uat`、betwin 的 `test`）。
- 环境配置来源；项目内置配置优先，只有用户或项目档案明确要求时才读取本地 `envs.secrets.yaml`。
- `@@BE` 断言清单（验证项、期望值、失败判定条件）。
- `@@BE` 自验证结果；没有时先阻塞或要求说明原因。
- `@@TL` 验收口径和 `@@BA` 风险结论；重要需求据此补充真实业务场景。

## 执行步骤

1. 识别项目内置配置、默认环境和可用验证命令。
2. 执行基础组件验证（DB、Redis、ES、MQ）。
3. 按断言清单执行业务验证，记录实际值。
4. 重要需求补充 3-7 个真实业务场景，并记录前置数据、操作步骤、期望状态、实际证据和清理方式。
5. 收集证据（日志、查询结果、接口响应）。
6. 输出断言比对报告和场景验证结果（通过/失败/阻塞）。

## 输出格式

- 环境准备结果
- 断言比对表（验证项/期望值/实际值/结论/证据）
- 风险与回滚建议

## 失败与升级

- 断言不清晰时先阻塞，回退给 `@@BE` 重新定义。
- `@@BE` 未自验证时先回退，除非无法自验证且已说明原因。
- 验证失败时先回流 `@@BE` 定位和修复；如果暴露边界、方案或验收口径问题，再升级 `@@BA` 或 `@@TL`。
- 关键断言失败时升级 `@@TL` 决策是否回滚。

## 禁止事项

- 不只做连通性，不做断言比对。
- 不输出无证据的“通过结论”。
