# SimpX 代码审查技能

## 适用场景

- 变更涉及资金、状态机、异步链路、回调等高风险域。
- 需要在交付前快速识别缺陷与回归风险。
- 需要明确是否建议阻塞交付时。

## 前置输入

- 变更范围与目标。
- `@@BE` 的实现和断言清单。
- `@@DEVOPS` 验证报告（如已有）。

## 执行步骤

1. 先按业务正确性和兼容性筛查高风险点。
2. 检查失败路径、幂等、重试、回滚逻辑是否完整。
3. 检查断言清单与验证报告是否一致。
4. 形成按严重度排序的问题清单。
5. 给出修复建议与是否阻塞交付建议。

## 输出格式

- 发现项（严重度：高/中/低）
- 风险说明
- 修复建议
- 放行建议（通过/阻塞）

## 失败与升级

- 证据不足时明确标记“待补证据”，不做强结论。
- 发现高风险缺陷时直接升级 `@@TL`。

## 禁止事项

- 不以样式问题代替风险分析。
- 不跳过验证证据直接给放行建议。
