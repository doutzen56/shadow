# SimpX 前端实现技能

## 适用场景

- 需要改前端页面、组件、路由、状态或 API 调用时。
- 需要保证实现符合项目现有前端栈和目录约定时。
- 需要输出可交付的前端实现步骤、变更文件清单和自验证结果时。

## 前置输入

- 需求目标与验收标准（`@@TL`）。
- 项目档案里的前端栈、构建命令、测试命令和模块边界；没写就先问，不猜框架。
- 接口契约和版本（后端接口由 `@@BA` 给出）。
- 任务契约里的允许修改路径。

## 执行步骤

1. 确认改哪些页面、组件、路由和状态，标出公共文件；公共文件只能由一个任务负责。
2. 先找项目里已有的请求封装、组件和工具函数，能复用就复用，不另起一套。
3. 按接口契约写 API 调用：入参、出参、错误码、加载和空状态都要处理；接口报错给用户能看懂的提示，不直接展示后端异常原文。
4. 安全检查：不用 `innerHTML` / `v-html` 直接渲染接口返回的内容；令牌不放在会被第三方脚本读到的地方；手机号、邮箱、证件号、银行卡号按要求脱敏展示；日志和埋点不带敏感字段。
5. 保持各站点模板、各端的已有差异，不为了统一改坏别的模板。
6. 自验证：按项目档案跑类型检查、Lint、构建和相关测试；项目没有这些命令时，写清手工验证步骤和实际结果。
7. 输出变更文件清单，核对没有超出允许修改路径。

## 输出格式

- 前端设计取舍（组件、状态、数据获取）
- 实现步骤
- 变更文件清单和契约版本
- 异常路径与兼容说明
- 自验证结果（命令、实际结果、失败信息）
- 断言清单（给 `@@QA`）

## 失败与升级

- 接口语义不清、契约冲突时，阻塞并升级 `@@TL`。
- 需要改公共组件、路由表或全局状态而任务没写这些路径时，先停下说明。

## 禁止事项

- 不猜项目用的框架和构建命令。
- 不绕过接口契约自己约定字段。
- 不改业务仓里的打包产物（文件名带哈希的 js、`.min.js`），要改源码再构建。
