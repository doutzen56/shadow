# 断言清单模板（@@BE）

## 使用时机

- 进入实现方案确认后，交给 `@@DEVOPS` 执行验证前。
- 任意需要“期望值 vs 实际值”闭环的改动。

说明：该模板用于提升一致性，不要求必须先生成文件；可直接在会话中结构化给出。

## 基本信息

- 项目标识：
- 需求/缺陷编号：
- 变更范围：
- 目标环境：`dev` / `test` / `uat`
- 输出人：`@@BE`
- 接收人：`@@DEVOPS`

## 断言清单（必填）

每条断言必须包含以下字段：

- 断言编号：
- 验证项：
- 期望值：
- 失败判定条件：
- 关联模块：
- 风险等级：高 / 中 / 低
- 备注：

## 建议分类

- 主链路断言（必须）
- 失败路径断言（必须）
- 兼容性断言（按需）
- 性能/容量断言（按需）

## 交付标准

- 至少 1 条主链路断言 + 1 条失败路径断言。
- 所有高风险断言必须写失败判定条件。
- 描述必须可执行，不允许模糊词（如“差不多”“基本正确”）。
