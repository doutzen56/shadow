# 验证证据包模板（@@DEVOPS）

## 使用时机

- `@@DEVOPS` 完成验证后提交交付结论前。
- `@@TL` 需要做通过/阻塞/回滚决策时。

说明：证据可以直接在会话中给出；目录化保存是可选增强，不是必须步骤。

## 目录规范

建议每次验证创建一个目录：

`reports/verification/<project-id>/<env>/<yyyymmdd-hhmm-task-id>/`

目录下建议包含：

- `summary.md`：本次验证总览与结论
- `assertion-results.md`：断言逐条比对
- `db/`：数据库查询证据
- `redis/`：缓存相关证据
- `mq/`：消息相关证据
- `api/`：接口响应证据
- `logs/`：关键日志片段

## 断言结果格式（必填）

每条断言必须包含：

- 断言编号
- 验证项
- 期望值
- 实际值
- 结论（通过 / 失败 / 阻塞）
- 证据路径

## 命名规范

- 文件命名建议：`<step-order>-<short-name>.md`
- 证据文件建议带时间戳，便于追溯。

## 安全要求

- 敏感信息必须脱敏。
- 禁止写入明文密钥、令牌、连接串。

## 失败升级

- 关键断言失败：立即标记阻塞并同步 `@@TL`。
- 证据不完整：不允许给“通过”结论。
- 禁止只整理材料不推动修复联动。
