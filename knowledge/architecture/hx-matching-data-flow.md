# HX.Matching 主数据流

## 总览

HX.Matching 的核心数据流围绕订单生命周期展开：下单、撮合、支付或提款、状态推进、回调通知、统计归档。

## 商户代收链路

1. 商户调用商户开放接口提交代收订单。
2. 接口完成签名、时间戳、商户状态、金额和渠道校验。
3. 核心服务创建充值订单，并返回收银台链接。
4. 收银台用户进入页面，系统拉取可用收款账户或渠道结果。
5. 订单状态通过用户支付、供应商回调、超时任务或后台人工处理推进。
6. 系统通过消息或后台服务向商户通知最终结果。

风险点：验签契约、订单号幂等、金额精度、收银台轮询、拉单锁、超时策略、回调补偿。

## 商户代付链路

1. 商户调用商户开放接口提交代付订单。
2. 接口完成验签、账户信息、金额、渠道和商户规则校验。
3. 核心服务创建提款订单，并根据渠道或供应商规则处理后续出款。
4. 后台任务或异步链路推进订单状态。
5. 系统回调商户，并在后台统计中体现资金变化。

风险点：资金字段、账号字段、渠道差异、回调重试、订单状态一致性。

## 合作方撮合链路

1. 合作方调用互通接口创建买家订单或卖家挂单。
2. 接口完成验签、用户画像字段、金额和渠道校验。
3. 核心撮合服务尝试分配收款账户。
4. 若立即匹配成功，返回收款账户；否则返回匹配中，合作方继续查询。
5. 后续通过支付、回调、超时任务推进状态。

风险点：撮合窗口、用户画像字段、同步等待、轮询策略、收款账户过期时间。

## 异步链路

后台任务进程集中处理：

- 消息队列消费。
- 商户回调通知。
- 渠道回调查询。
- 订单超时处理。
- 统计和报表数据同步。
- 离线导出。
- Telegram 通知。

异步链路的风险不只影响后台；一旦后台任务进程不可用，前台订单可能表现为长期处理中、回调延迟或统计失真。

## SimpX 分析规则

分析任何 HX.Matching 需求时，先问四个问题：

1. 这是同步接口链路，还是异步后台链路？
2. 是否影响订单状态或资金字段？
3. 是否改变外部接口契约或签名规则？
4. 是否需要补回调、超时、统计或人工处理路径？
