# 商户与合作方接口契约摘要

## 基础契约

商户开放接口和合作方互通接口都采用请求体签名方式，并把业务结果放在响应体中表达。

共同特征：

- 请求格式为 JSON。
- 签名算法为 MD5。
- 时间戳使用 13 位毫秒时间戳。
- 时间戳与服务端时间偏差超过约一分钟时视为过期。
- 业务成功通常以业务码为准。
- 签名字段、空值过滤、排序规则必须严格保持一致。

## 商户接口重点

商户接口覆盖代收下单、代付下单、查单和收银台相关能力。

关键约束：

- 代收成功返回收银台链接。
- 代付需要收款账号、银行等账户信息。
- 金额最小值和小数位有明确约束。
- 商户订单号需要保证商户侧唯一。
- 回调地址决定异步通知路径。

风险点：

- 修改请求字段会影响签名。
- 修改响应字段会影响商户接入。
- 修改订单状态枚举需要兼容外部系统。
- 修改金额精度或最小金额会影响资金链路。

## 合作方接口重点

合作方接口覆盖买家下单、收款账户查询、卖家挂单等撮合场景。

关键约束：

- 合作方下单可能同步返回收款账户，也可能返回匹配中。
- 用户成交次数、成功率、历史最大金额等画像字段会参与撮合判断。
- 查询接口需要支持平台订单号和合作方订单号。
- 服务端超时时，调用方需要先判断 HTTP 状态，再解析业务响应。

风险点：

- 合作方签名拼串字段名与请求体命名风格可能不同，不能随意统一。
- 画像字段缺失会影响撮合池准入。
- 收款账户过期时间需要作为倒计时依据。

## SimpX 审查规则

涉及接口契约时，至少检查：

1. 签名规则是否变化。
2. 字段必填性是否变化。
3. 金额、时间、订单号约束是否变化。
4. 响应业务码和状态是否变化。
5. 回调和查单是否与主流程一致。
