# 支付撮合术语表

## 核心角色

| 术语 | 含义 |
| --- | --- |
| 商户 | 接入平台发起代收或代付的业务方 |
| 合作方 | 通过互通接口参与撮合链路的外部平台 |
| 供应商 | 提供支付、收款账户、出款或渠道能力的一方 |
| 渠道 | 平台内用于区分支付方式、供应商能力或业务路径的配置单元 |
| 用户 | 商户或合作方传入的终端用户身份，用于风控、撮合和订单追踪 |

## 订单概念

| 术语 | 含义 |
| --- | --- |
| 代收 | 商户发起收款订单，终端用户付款后平台通知商户结果 |
| 代付 | 商户发起出款订单，平台或供应商向指定账户付款 |
| 撮合 | 系统根据订单、金额、用户画像、渠道和收款账户状态完成买卖双方匹配 |
| 挂单 | 卖家侧或合作方侧提供可被匹配的收款资源 |
| 收银台 | 终端用户完成付款的页面或接口入口 |
| 回调 | 平台向商户或合作方通知订单最终状态的异步请求 |

## 状态与风险

| 术语 | 含义 |
| --- | --- |
| 处理中 | 订单已创建但未进入最终状态 |
| 已成功 | 订单完成且资金或业务结果已确认 |
| 已失败 | 订单不可继续推进，需要明确失败原因 |
| 已取消 | 订单因超时、人工或业务规则被取消 |
| 匹配中 | 撮合尚未分配到可用收款账户 |
| 超时 | 订单、接口、锁或外部调用超过允许窗口 |

## SimpX 使用提示

涉及金额、订单状态、收款账户、回调、超时和撮合规则的需求，都应按高风险任务处理，由后端架构、后端实现和测试质量角色共同参与。
