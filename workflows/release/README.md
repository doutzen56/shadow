# 发布流程

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

将实现结果在测试环境完成可复验交付，输出风险、未验证项和回滚结论。

`release` 只处理发布交付或复验任务，不负责需求拆解和实现闭环。尚未完成 `feature-development` 断言、自验证和失败修复的任务，不得直接用本流程替代。

## 输入

- 项目标识与版本说明。
- 目标环境：按项目 `envs.yaml` 的 `default_envs`（如 hx-matching：`dev`、`uat`；betwin：`test`）。
- 对应环境配置：项目内置配置优先；只有用户或项目档案明确要求时才读取 `envs.secrets.yaml`。
- `@@BE` / `@@FE` 输出的验证断言清单。

## 分工

- `@@DEVOPS` 给环境和交付结论：环境、配置来源、组件连通、部署冒烟、回滚方式。
- `@@QA` 给质量结论：断言比对、主链路和场景验证。
- `@@TL` 按两边的证据做技术放行。

## 步骤

1. `@@DEVOPS` 识别项目内置配置、默认环境和可用验证命令。
2. `@@DEVOPS` 执行任务涉及组件验证（DB、Redis、ES、MQ 等）和部署冒烟，给出环境可用证据。
3. `@@QA` 按断言清单执行接口与主链路验证；重要需求补充真实业务场景。
4. 验证失败时，产品逻辑问题回流 `@@BE` / `@@FE`，环境问题回流 `@@DEVOPS`；如果暴露边界、方案或验收口径问题，再升级 `@@BA` 或 `@@TL`。
5. `@@QA` 复测；如仍失败，回到步骤 4 继续联动修复（最多 2 轮）。
6. 超过 2 轮仍失败，停止循环并提交给用户决策。
7. `@@TL` 判断是否通过当前阶段交付或阻塞/回滚。

## 输出

- 环境准备结果（`@@DEVOPS`）。
- 组件验证和部署冒烟结果（`@@DEVOPS`，DB/Redis/ES/MQ 按任务实际涉及范围裁剪）。
- 断言比对结果（`@@QA`，期望值、实际值、结论、证据）。
- 场景验证结果（前置数据、操作步骤、期望状态、实际证据、清理方式）。
- 风险列表、阻塞项和回滚建议。
- 未验证项。
- 交付结论（通过/失败/阻塞）。
- 收口结果（失败断言的处理结论）。

要落文件时，测试计划用 `templates/test-plan/README.md`，放行判断用 `templates/release-gate/README.md`。

## 回滚条件

- 核心主链路失败且短期无法修复。
- 影响资金、订单、权限或核心用户路径的数据一致性验证失败。
- 基础组件验证存在高风险不确定项。
- 影响资金、订单、权限、接口契约、数据一致性、生产配置或核心用户路径的断言缺少实际值或证据，无法复验。
- 影响上述对象的失败断言无修复动作且无 TL 决策。
- 连续 2 轮修复仍失败且未升级用户决策。
