# 发布流程

## 目标

将实现结果在测试环境完成可复验交付，输出风险和回滚结论。

## 输入

- 项目标识与版本说明。
- 目标环境：`dev`、`test`、`uat`。
- 对应环境配置：`envs.yaml`。
- 本地密钥文件：`envs.secrets.yaml`（不入库）。
- `@@BE` 输出的验证断言清单。

## 一阶段步骤

1. `@@DEVOPS` 校验环境配置和密钥可用性。
2. `@@DEVOPS` 执行 DB、Redis、MQ 连接与读写验证。
3. `@@DEVOPS` 按断言清单执行接口冒烟与主链路验证。
4. `@@BE` 配合定位失败项并修复可修复问题。
5. `@@DEVOPS` 复测；如仍失败，回到步骤 4 继续联动修复（最多 2 轮）。
6. 超过 2 轮仍失败，停止循环并提交给用户决策。
7. `@@TL` 判断是否通过当前阶段交付或阻塞/回滚。

## 输出

- 环境准备结果。
- 组件验证结果（DB/Redis/MQ）。
- 断言比对结果（期望值、实际值、结论、证据）。
- 风险列表、阻塞项和回滚建议。
- 交付结论（通过/失败/阻塞）。
- 闭环结果（失败断言的处理结论）。

## 回滚条件

- 核心主链路失败且短期无法修复。
- 关键数据一致性验证失败。
- 基础组件验证存在高风险不确定项。
- 关键断言缺少实际值或证据，无法复验。
- 关键失败断言无修复动作且无 TL 决策。
- 连续 2 轮修复仍失败且未升级用户决策。
