# 需求到设计

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

把需求收敛为有责任角色、影响范围、验证方式和收口条件的边界方案与验收口径。

## 输入

- 需求目标与业务背景
- 约束条件（时间、范围、不可改边界）
- 项目标识与当前环境

## 标准步骤

1. `@@TL` 明确目标、优先级和验收标准。
2. `@@X` 按 `templates/knowledge-reuse-check` 做知识复用检查：先查项目档案和索引，再按角色矩阵取 Top-K。
3. `@@BA` 输出边界分析与风险分级，说明采用或未采用哪些架构知识。
4. `@@BE` 评估实现可行性与断言草案，引用必要的代码摘要或说明未命中原因。
5. `@@DEVOPS` 评估环境验证可行性与依赖缺口，列出需要的验证知识或项目内置命令。
6. `@@TL` 给出设计阶段结论（继续/阻塞/缩范围）。

## 输出

- 设计目标清单
- 边界与风险结论；风险要说明影响对象、触发条件和失败后果
- 知识复用结果；未复用时说明原因
- 初版实现与验证路径
- 阶段决策结论

## 收口检查

- 边界不清或关键约束不明，不进入下一阶段。
- 风险无分级依据，不进入下一阶段。
- 知识复用超过预算仍不清楚时，升级 `@@TL` 决策。
- 关键争议超过 2 轮无收敛，交用户决策。
