# 需求到设计

## 目标

把需求收敛为可执行的边界方案与验收口径。

## 输入

- 需求目标与业务背景
- 约束条件（时间、范围、不可改边界）
- 项目标识与当前环境

## 标准步骤

1. `@@TL` 明确目标、优先级和验收标准。
2. `@@BA` 输出边界分析与风险分级。
3. `@@BE` 评估实现可行性与断言草案。
4. `@@DEVOPS` 评估环境验证可行性与依赖缺口。
5. `@@TL` 给出设计阶段结论（继续/阻塞/缩范围）。

## 输出

- 设计目标清单
- 边界与风险结论
- 初版实现与验证路径
- 阶段决策结论

## 门禁规则

- 边界不清或关键约束不明，不进入下一阶段。
- 风险无分级依据，不进入下一阶段。
- 关键争议超过 2 轮无收敛，交用户决策。
