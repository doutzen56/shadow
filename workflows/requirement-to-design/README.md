# 需求到设计

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

把需求收敛为有责任角色、影响范围、契约、验证方式和收口条件的边界方案与验收口径。

## 输入

- 需求目标与业务背景
- 约束条件（时间、范围、不可改边界）
- 项目标识与当前环境

## 按影响范围裁剪

- 局部缺陷或单模块小改：可以跳过系统级设计，直接进领域设计。
- 跨模块、跨前后端、改公共契约或高风险：必须有 `@@TL` 系统级约束和契约审查。

## 标准步骤

1. `@@TL` 明确目标、优先级和验收标准；跨领域时给出系统级约束（系统边界、身份权限、部署边界、关键数据模型）。
2. `@@X` 列出受影响的领域（前端/后端/数据/基础设施）和每个领域的责任角色。
3. `@@X` 按 `templates/knowledge-reuse-check` 做知识复用检查：先查项目档案和索引，再按角色矩阵取 Top-K。
4. `@@BA` 输出后端边界分析与风险分级；涉及前端时 `@@FE` 输出前端方案；说明采用或未采用哪些架构知识。
5. 有接口、数据或共享组件契约要新建或变更时，`@@BA` / `@@FE` 草拟契约，`@@QA` 提出验收和测试约束，`@@TL` 批准或打回。
6. `@@BE` / `@@FE` 评估实现可行性与断言草案，引用必要的代码摘要或说明未命中原因。
7. `@@QA` 评估验证可行性；需要真实环境时 `@@DEVOPS` 评估环境依赖缺口，列出需要的项目内置命令。
8. 要拆成多个任务时，`@@X` 给出初始任务图：硬依赖、可并行候选和理由。
9. `@@TL` 给出设计阶段结论（继续/阻塞/缩范围）。

## 输出

- 设计目标清单
- 系统级约束（跨领域时）
- 受影响领域和责任角色
- 边界与风险结论；风险要说明影响对象、触发条件和失败后果
- 契约清单和状态（draft / review / approved）
- 知识复用结果；未复用时说明原因
- 初版实现与验证路径；拆多个任务时附初始任务图
- 验收条件和证据要求
- 必须由用户拍板的业务取舍
- 阶段决策结论

要落文件时用 `templates/technical-design/README.md`；架构取舍要长期留存时用 `templates/adr/README.md`；契约用 `contracts/templates/`。

## 收口检查

- 边界不清或关键约束不明，不进入下一阶段。
- 风险无分级依据，不进入下一阶段。
- 跨领域契约没批准，依赖它的任务不进入实现。
- 知识复用超过预算仍不清楚时，升级 `@@TL` 决策。
- 关键争议超过 2 轮无收敛，交用户决策。
