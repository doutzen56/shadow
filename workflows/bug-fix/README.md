# 缺陷修复

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

定位缺陷、快速修复、验证关闭并控制回归风险。

## 输入

- 缺陷现象与复现条件
- 影响范围和风险等级
- 相关代码与日志线索

## 标准步骤

1. `@@BE` 复现问题并定位根因。
2. `@@BA` 判断是否涉及边界或架构风险。
3. `@@BE` 提交修复方案和断言更新。
4. `@@DEVOPS` 执行修复后验证并反馈实际结果。
5. 必要时循环修复-复测，`@@TL` 最终决策。
6. `@@X` 判断是否形成候选事故、反例或模式卡；不沉淀时说明原因。

## 输出

- 根因说明
- 修复动作
- 验证结果；必须包含命令或手工步骤、实际结果、是否通过
- 未验证项
- 风险与回滚建议

## 收口检查

- 未复现或根因不明不得宣告修复完成。
- 修复后未验证不得关闭。
- 修复-复测超过 2 轮仍失败，交用户决策。
- 缺陷暴露可复用失败模式时，进入 `knowledge-growth-loop`。
