# 设计到编码

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

把设计方案转成有责任角色、允许修改路径、依赖、契约引用、断言和回滚建议的编码任务；拆成多个任务时产出可校验的任务图。

## 输入

- `@@TL` 设计阶段结论和系统级约束
- `@@BA` 后端边界与风险结论；涉及前端时 `@@FE` 前端方案
- 契约清单和状态（有跨领域或公共契约时）
- 相关模块与依赖链路

## 标准步骤

1. `@@BE` / `@@FE` 读取领域边界结论，并按角色矩阵检索实现相关代码摘要和模式卡。
2. `@@BE` / `@@FE` 拆分实现任务和变更范围，说明采用或未采用哪些实现知识。
3. `@@BE` / `@@FE` 输出断言清单（验证项/前置条件/期望值/失败判定/建议验证方式）。
4. `@@X` 把任务整理成最小可交付单元：每个任务写清 owner、输入、输出、允许修改路径、依赖、契约引用和验收证据。拆成两个以上任务时按 `contracts/templates/task.yaml` 落文件。
5. `@@X` 按 `orchestration/policies/parallelism.yaml` 给每个任务判 P0/P1/P2/P3 并写依据；P1 要确认契约已批准，P2 要先拆出可独立的部分。
6. `@@X` 跑 `python orchestration/tools/task_graph_validate.py <任务目录>`，确认没有循环依赖、依赖都存在、每个任务都有 owner 和验收条件。
7. `@@BA` / `@@FE` 复核是否越过边界。
8. `@@QA` 确认验证路径是否可执行，补充验证知识或场景模板；需要真实环境时 `@@DEVOPS` 确认环境可准备。
9. `@@TL` 只审系统级、公共契约和高风险取舍，确认是否进入实现执行；规则内的普通实现细节不逐项审批。

## 输出

- 实现任务清单（或任务图文件和校验结果）
- 每个任务的并行类别和依据
- 知识复用结果和代码摘要引用
- 断言清单
- 自验证要求
- 实现质量自检要求
- 风险与兼容说明
- 进入实现阶段结论

## 收口检查

- 无断言清单不得进入实现。
- 越边界改动未获 BA/FE/TL 确认不得进入实现。
- 任务图校验没过、契约没批准的任务不得进入实现。
- 代码摘要与当前源码冲突时，以当前源码为准并记录冲突。
- 分歧超过 2 轮无收敛，交用户决策。
- 本流程只到“可以进入实现”为止；实际编码、验证和交付按 `workflows/feature-development` 的步骤 4 起推进，不在这里宣告完成。
