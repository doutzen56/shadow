# 设计到编码

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

把设计方案转成有责任角色、目标文件或模块、动作、断言和回滚建议的编码任务。

## 输入

- `@@TL` 设计阶段结论
- `@@BA` 边界与风险结论
- 相关模块与依赖链路

## 标准步骤

1. `@@BE` 先读取 `@@BA` 边界结论，并按角色矩阵检索实现相关代码摘要和模式卡。
2. `@@BE` 拆分实现任务和变更范围，说明采用或未采用哪些实现知识。
3. `@@BE` 输出断言清单（验证项/前置条件/期望值/失败判定/建议验证方式）。
4. `@@BA` 复核是否越过边界。
5. `@@DEVOPS` 确认验证路径是否可执行，并补充验证知识或场景模板。
6. `@@TL` 确认是否进入实现执行。

## 输出

- 实现任务清单
- 知识复用结果和代码摘要引用
- 断言清单
- BE 自验证要求
- 实现质量自检要求
- 风险与兼容说明
- 进入实现阶段结论

## 收口检查

- 无断言清单不得进入实现。
- 越边界改动未获 BA/TL 确认不得进入实现。
- 代码摘要与当前源码冲突时，以当前源码为准并记录冲突。
- 分歧超过 2 轮无收敛，交用户决策。
- 本流程只到“可以进入实现”为止；实际编码、验证和交付按 `workflows/feature-development` 的步骤 3 起推进，不在这里宣告完成。
