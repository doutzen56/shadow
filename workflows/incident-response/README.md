# 事故响应

## 通用前置检查

执行本流程前，必须先完成 `workflows/_shared/` 中的任务入口、权限、证据、验证、角色交接和完成检查。

## 目标

先止血、再定位、再验证恢复，最后形成可复用结论。

## 输入

- 事故现象与影响范围
- 当前环境与告警线索
- 已知变更和时间线

## 标准步骤

1. `@@TL` 定义优先级与止血目标。
2. `@@BE` 与 `@@DEVOPS` 联合定位根因线索。
3. `@@BA` 判断是否涉及边界或系统性风险。
4. `@@BE` 提交修复动作，`@@DEVOPS` 执行恢复验证。
5. `@@TL` 决策恢复/阻塞/回滚并安排复盘。
6. `@@X` 汇总事故线索，`@@TL` 按 `knowledge-growth-loop` 判断是否沉淀事故知识，或写明不沉淀原因。

## 输出

- 事故影响说明
- 根因与修复动作
- 恢复验证结果；必须包含命令或手工步骤、实际结果、是否通过
- 未验证项
- 后续治理建议

示例：`workflows/incident-response/examples/hx-matching-threadpool-starvation.md`。

## 收口检查

- 未止血前不得扩散改动范围。
- 恢复动作未验证不得宣告恢复完成。
- 超过 2 轮仍无法恢复，交用户决策。
- 事故复盘结论进入 `knowledge-growth-loop`，由 `@@TL` 判断入库，用户周审修正。
