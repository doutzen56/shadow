# 角色交接检查

## 用途

角色交接块是会话内的结构化输出，不是默认临时文件。只有用户明确要求沉淀、需要跨会话继续、要写 ADR 或知识候选时，才写入文件。

## 基本规则

`@@X` 推进角色链路时，每一棒必须有交接块。没有交接块，不得声称某角色职责已经完成，也不得进入下一角色。

没有真实派发独立子任务时，不写“已交给独立角色”。应写“进入 `@@BA` 职责阶段”“进入 `@@BE` 职责阶段”等可追溯表述。

## 交接块格式

- 当前阶段：当前处于哪个角色职责阶段。
- 责任角色：负责本阶段结论的角色。
- 角色定义：本会话读过的 `agents/<role>/system.md` 路径；没读过不能开这一棒。
- 执行方式：会话内职责阶段，或真实子任务（写子任务标识，按 `simpx-core.mdc` 的“子任务证据回流”收回结果）。
- 输入：上一棒给出的目标、约束、证据和待处理问题。
- 动作：本阶段实际做了什么；没有实际动作时写“未执行”。
- 输出：本阶段给下一棒的结论或清单。
- 证据：文档、代码、命令、验证或人工确认。
- 知识引用：本阶段采用的知识、代码摘要和丢弃原因；没有使用时写“未使用”。
- 风险：未闭合风险和触发条件。
- 下一棒：下一责任角色、需要的输入和是否允许进入下一阶段。

## 任务字段（有任务图或契约时加上）

只有一个任务、没有契约时可以不写。拆成两个以上任务、有契约、要跨会话追踪时必须写：

```yaml
task_id: "TASK-..."
owner_role: "@@FE"
contract_refs:
  - id: "API-..."
    version: "1.0.0"
dependency_status: satisfied   # satisfied / waiting / blocked
parallel_class: P1             # 按 orchestration/policies/parallelism.yaml
allowed_paths:
  - "frontend/src/features/users/**"
workspace_ref: null            # 有隔离工作区时写路径；没有就写 null，不能说已隔离
state_before: Ready
state_after: Implemented
evidence_refs: []
```

需要跨会话追踪、自动校验或并行执行时，把任务契约写成文件，用 `orchestration/tools/` 校验。

## 各角色最低输出

- `@@TL`：目标、优先级、验收标准、系统级约束（跨领域时）、公共契约批准结论、是否需要用户拍板。
- `@@BA`：后端边界判断、风险等级和依据、后端接口契约草案、给 `@@BE` 的实现约束、给 `@@QA` 的验证重点。
- `@@FE`：前端方案和取舍、允许修改路径、契约引用、变更文件清单、自验证结果（类型检查、Lint、构建、测试）。
- `@@BE`：实现步骤、变更文件清单、契约版本、断言清单、BE 自验证结果、异常和兼容路径。
- `@@QA`：测试计划、执行命令或手工步骤、期望值、实际值、结论、失败项归属、未覆盖项、质量结论建议。
- `@@DEVOPS`：环境或配置来源、组件连通证据、部署冒烟的命令和实际结果、回滚方式、未验证项。
- `reviewer`：发现项、严重度、证据、修复建议、是否建议阻塞。
- `researcher`：调研范围、方案对比、实验或资料证据、不确定项。

## 不允许

- 用一句“已交给某角色”代替交接块。
- 没读该角色的 `system.md` 就输出该角色的最低输出。
- 子任务没有标识或证据，就写“子任务已完成”。
- 用总结代替证据。
- 没有 `@@BE` / `@@FE` 断言清单和自验证结果就进入 `@@QA` 验证阶段；无法自验证时必须说明原因。
- 没有实际命令、实际值或人工确认，就写“验证通过”。
- 没有真实独立执行环境和任务标识，就写“已并行执行”；只能写“按角色分阶段处理”。
