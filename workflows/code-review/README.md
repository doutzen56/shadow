# 代码审查

## 目标

在交付前识别高风险缺陷并给出放行建议。

## 输入

- 变更范围与目标
- `@@BE` 断言清单
- `@@DEVOPS` 验证结果（如有）

## 标准步骤

1. `reviewer` 按业务正确性、兼容性、稳定性审查。
2. 输出问题清单（高/中/低）和证据。
3. `@@BE` 对高风险项给修复动作。
4. `@@DEVOPS` 对修复项复测关键断言。
5. `@@TL` 基于证据给放行结论。

## 输出

- 审查问题清单
- 修复与复测结果
- 放行建议（通过/阻塞/回滚）

## 门禁规则

- 高风险问题未闭合不得通过。
- 证据不足不得通过。
- 同一问题修复-复测超过 2 轮，交用户决策。
