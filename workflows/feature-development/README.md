# 功能开发

## 目标

通过 `@@X -> @@TL -> @@BA -> @@BE -> @@DEVOPS -> @@TL` 的协作链路，完成从需求到测试环境交付的闭环。

## 输入

- 需求描述和业务目标。
- 项目标识（如 `hx-matching`、`betwin`）。
- 目标环境（默认 `dev`、`test`、`uat`）。
- 约束条件（不能动的边界、上线窗口、回滚要求）。

## 一阶段步骤

1. `@@TL` 明确目标、优先级和验收标准。
2. `@@BA` 分析边界、风险、兼容点和技术取舍。
3. `@@BE` 产出实现步骤、改动清单和验证断言清单（期望值、失败判定条件）。
4. `@@DEVOPS` 准备环境并执行基础组件验证（DB、Redis、MQ）。
5. `@@DEVOPS` 按断言清单执行验证，记录每条断言的实际值与证据。
6. 如果存在失败断言，`@@BE` 与 `@@BA` 联动修复后回到步骤 5 复测（最多 2 轮）。
7. 超过 2 轮仍失败，停止循环并提交给用户决策。
8. `@@TL` 做最终取舍，确认是否进入下一阶段。

## 输出

- 架构影响说明。
- 实现执行清单。
- 断言比对报告（期望值/实际值/结论/证据）。
- 交付结论和回滚建议。
- 问题闭环记录（失败项 -> 修复动作 -> 复测结果）。

## 验收门禁

- 角色链路完整执行。
- 至少覆盖一条主链路和一条失败路径。
- 关键组件验证通过或给出阻塞说明。
- 交付报告可复验，且每条关键断言都有期望值和实际值。
- 失败断言必须完成“修复或阻塞决策”，不能只停在报告阶段。
- 连续 2 轮修复仍失败时，必须升级为用户决策，不允许继续死循环。
