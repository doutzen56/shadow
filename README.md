# SimpX

SimpX 是一个个人智能技术团队框架，用来把技术负责人的判断、智能角色分工、工程流程、项目风格和长期知识沉淀组织起来。

它不是一次性的提示词集合，而是一套可复用、可演进、可沉淀的个人技术组织系统。

## 一阶段目标

一阶段先让团队能够稳定工作：

- 明确技术负责人的职责与决策边界。
- 固定核心智能成员：调度者、后端架构、后端实现、环境与交付。
- 建立业务交付型与架构治理型两类项目打法。
- 使用统一工作流完成需求、设计、实现、验证和交付。
- 把经验、决策和教训沉淀到长期知识目录。

## SimpX 1.0 成员

| 正式编号 | 召唤标签 | 职责 |
| --- | --- | --- |
| `X-01` | `@@X` | 团队调度者 |
| `TL-01` | `@@TL` | 技术负责人 |
| `BA-01` | `@@BA` | 后端架构工程师 |
| `BE-01` | `@@BE` | 后端实现工程师 |
| `DEVOPS-01` | `@@DEVOPS` | 环境与交付工程师 |

正式编号用于文档、职责边界和长期沉淀；召唤标签用于日常对话和任务分派。

## 辅助成员

| 标识 | 用途 | 启用方式 |
| --- | --- | --- |
| `reviewer` | 高风险改动审查与缺陷识别 | 按 `@@TL` 或 `@@X` 指派 |
| `researcher` | 方案调研、实验与决策依据补充 | 按 `@@TL` 或 `@@X` 指派 |

## 如何召唤成员

```text
@@X：按项目风格调度角色，产出执行顺序。
@@TL：做目标确认、优先级判断和最终取舍。
@@BA：分析架构边界和技术风险。
@@BE：拆后端实现步骤和影响范围。
@@DEVOPS：配置环境并执行测试环境交付验证。
```

需要多人协作时，可以组合召唤：

```text
@@TL + @@BA + @@BE：一起评估后端需求方案。
@@BE + @@DEVOPS：实现后完成环境验证与交付检查。
@@X：按项目风格完成任务分析、方案、验证和沉淀。
```

## Agent 工作入口

Agent 开始工作前，按以下顺序读取和判断：

1. `.cursor/rules/`：当前必须执行的硬规则。
2. `config/active-rules.yaml`：当前生效规则清单和优先级。
3. `config/simpx.yaml`：成员、召唤标签和默认协作顺序。
4. `workflows/_shared/`：任务入口、权限、证据和完成检查。
5. 当前任务对应的 `workflows/<name>/README.md`。
6. 召唤标签对应的 `agents/<role>/system.md`。
7. 当前业务仓映射到的项目档案。

规则冲突时，以用户当前消息和 `config/active-rules.yaml` 登记的生效规则为准。

## 建设原则

- 先可用，再完整。
- 先沉淀方法，再建设工具。
- 先稳定角色，再扩展能力。
- 先服务真实项目，再追求平台化。

## 成熟度

- 已启用：当前一阶段需要认真维护。
- 草稿：一阶段会逐步完善。
- 规划：未来阶段建设。
- 实验：用于探索，不进入稳定流程。
