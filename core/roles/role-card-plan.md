# SimpX 1.0 角色卡规划

## 目标

角色卡用于回答“召唤成员以后，他应该如何工作”。命名和召唤标签解决的是入口问题，角色卡解决的是职责、输入、输出、步骤和边界问题。

## 需要制定的角色卡

| 正式编号 | 召唤标签 | 角色卡主题 |
| --- | --- | --- |
| `TL-01` | `@@TL` | 技术负责人角色卡 |
| `BA-01` | `@@BA` | 后端架构角色卡 |
| `BE-01` | `@@BE` | 后端实现角色卡 |
| `QA-01` | `@@QA` | 测试质量角色卡 |
| `FE-01` | `@@FE` | 前端工程角色卡 |

## 每张角色卡的结构

每张角色卡应包含：

- 角色定位
- 适用场景
- 输入要求
- 输出格式
- 标准工作步骤
- 不负责什么
- 常见召唤语
- 与其他成员的协作方式
- 在企业稳定型项目中的注意事项
- 在业务交付型项目中的注意事项
- 在架构治理型项目中的注意事项

## 优先顺序

1. 先制定 `@@BE`，因为后端实现会最频繁参与真实任务。
2. 再制定 `@@QA`，保证每次实现前都有测试和回归视角。
3. 再制定 `@@BA`，用于处理边界、架构风险和技术债。
4. 再制定 `@@TL`，明确你的决策方式和验收口径。
5. 最后制定 `@@FE`，在涉及页面和接口联调时启用。

## 完成标准

五张角色卡完成后，SimpX 1.0 应能支持：

- 单独召唤某个成员完成专业分析。
- 多成员协作完成需求评审。
- 按项目风格调整输出深度。
- 在任务结束时沉淀可复用经验。
