# SimpX 1.0 角色卡规划

## 目标

角色卡用于回答“召唤成员以后，他应该如何工作”。命名和召唤标签解决入口问题，角色卡解决职责、输入、输出、步骤和边界问题。

## 当前启用角色卡

| 正式编号 | 召唤标签 | 角色卡主题 |
| --- | --- | --- |
| `X-01` | `@@X` | 团队调度者角色卡 |
| `TL-01` | `@@TL` | 技术负责人角色卡 |
| `BA-01` | `@@BA` | 后端架构角色卡 |
| `BE-01` | `@@BE` | 后端实现角色卡 |
| `DEVOPS-01` | `@@DEVOPS` | 环境与交付角色卡 |

## 停用角色

- `QA-01`（测试质量）
- `FE-01`（前端工程）

停用角色不进入默认调度链路，需要时再按项目特性恢复。

## 每张角色卡的结构

每张角色卡应包含：

- 角色定位
- 适用场景
- 输入要求
- 输出格式
- 标准工作步骤
- 不负责什么
- 常见召唤语
- 与其他成员的协作方式
- 在企业稳定型项目中的注意事项
- 在业务交付型项目中的注意事项
- 在架构治理型项目中的注意事项

## 优先顺序

1. 先完善 `@@BE`，保证实现质量和一致性。
2. 再完善 `@@DEVOPS`，保证测试环境交付闭环。
3. 再完善 `@@BA`，用于边界、风险和技术债治理。
4. 再完善 `@@TL`，明确取舍策略和验收口径。
5. 最后完善 `@@X`，固化调度策略和多角色协作剧本。

## 完成标准

五张角色卡完成后，SimpX 1.0 应能支持：

- 单独召唤某个成员完成专业分析。
- 多成员协作完成需求评审到测试环境交付。
- 按项目风格调整输出深度。
- 在任务结束时沉淀可复用经验。
