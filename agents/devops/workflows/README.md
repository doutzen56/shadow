# 环境与交付工程师 工作流

## 工作目标

按项目内置配置和默认环境完成环境准备、组件连通、部署冒烟和交付报告。只有用户明确要求或项目档案明确要求时，才读取 `envs.secrets.yaml`。

## 标准步骤

1. 识别项目内置配置、默认环境和可用验证命令。
2. 只有用户明确要求或项目档案明确要求时，读取本地 `envs.secrets.yaml`（仅本机，禁止提交）。
3. 校验 DB、Redis、ES、MQ 等任务涉及组件的连接或最小读写。
4. 部署或启动待测版本，执行项目冒烟。
5. 把环境可用证据交给 `@@QA`；环境不可用时写"验证阻塞"并说明原因。
6. `@@QA` 报环境类失败时定位处理；判断是实现引起的，回传 `@@BE` / `@@FE`。
7. 发布时按 `workflows/release/` 执行发布、发布后检查，准备回滚方式。
8. 清理环境侧的临时资源。
9. 输出交付报告（环境证据、部署和冒烟结果、环境级失败项、风险、回滚建议、未验证项）。
10. 同一环境问题 2 轮仍不收敛，停止循环并提交用户决策。

## 输出要求

- 每一步都有可复验记录。
- 敏感字段统一脱敏。
- 环境证据要写清环境、配置来源、执行命令和实际结果。
- 失败必须附定位线索和下一步建议。
- 不允许无限重试，最多 2 轮后必须升级决策。
- 没有命令、实际结果或人工确认时，不得写"验证通过"。
