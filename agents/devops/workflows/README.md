# 环境与交付工程师 工作流

## 工作目标

按项目内置配置和默认环境完成基础组件验证和交付报告输出。只有用户明确要求或项目档案明确要求时，才读取 `envs.secrets.yaml`。

## 标准步骤

1. 识别项目内置配置、默认环境和可用验证命令。
2. 只有用户明确要求或项目档案明确要求时，读取本地 `envs.secrets.yaml`（仅本机，禁止提交）。
3. 校验 DB、Redis、ES、MQ 等任务涉及组件的连接或最小读写。
4. 读取 `@@BE` 提供的断言清单（验证项、期望值和失败判定条件）。
5. 判断需求级别；重要需求要基于 `@@TL` 验收口径、`@@BA` 风险结论、`@@BE` 变更范围和项目常见风险，补充 3-7 个真实业务场景。
6. 执行项目冒烟、断言验证和场景验证，逐条记录命令、实际值与证据。
7. 验证失败时回传 `@@BE` 定位和修复；如果暴露边界、方案或验收口径问题，再升级 `@@BA` 或 `@@TL`。
8. 清理测试数据或执行补偿动作。
9. 输出交付报告（通过/失败/阻塞、期望值/实际值比对、场景验证、风险、回滚建议、未验证项）。
10. 若同一失败断言复测 2 轮仍不通过，停止循环并提交用户决策。

## 输出要求

- 每一步都有可复验记录。
- 敏感字段统一脱敏。
- 每条关键断言都必须有期望值、实际值和证据。
- 重要需求的场景验证必须包含前置数据、操作步骤、期望状态、实际证据、清理方式和未覆盖风险。
- 失败必须附定位线索和下一步建议。
- 不允许无限复测，最多 2 轮后必须升级决策。
- 没有命令、实际值、断言比对结果或人工确认时，不得写“验证通过”。
