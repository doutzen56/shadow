# 代码审查员 工作流

## 目标

在交付前识别高风险缺陷，给出严重度排序和阻塞建议。

## 标准步骤

1. 读取变更范围、断言清单和验证报告。
2. 优先审查行为正确性、安全性、数据或状态一致性、兼容性和稳定性。
3. 检查失败路径、幂等、回滚和异常处理。
4. 检查复用性、扩展性和过度设计风险；不把个人风格问题排在业务风险前面。
5. 输出问题清单并标注严重度（高/中/低）。
6. 给出修复建议和是否阻塞交付建议。
7. 若问题超过 2 轮仍未收敛，建议交用户决策。

## 输出要求

- 审查发现项（按严重度排序）
- 风险说明
- 修复动作建议
- 交付建议（通过/阻塞）
- 过度设计或复用不足的替代建议（如有）
