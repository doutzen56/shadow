# 质量与测试工程师 工作流

## 目标

按验收口径独立验证实现结果，给出有证据的质量结论。

## 标准步骤

1. 读取 `@@TL` 验收口径、`@@BA` 风险结论、`@@BE` / `@@FE` 的变更清单、断言清单和自验证结果。
2. 判断需求级别，写测试计划；重要需求补 3-7 个真实业务场景。同时标出哪些断言/场景必须走页面验证。
3. 需要真实环境时，先拿 `@@DEVOPS` 的环境可用证据（含可打开的页面地址与登录方式）；没有就写"验证阻塞"。
4. 有页面断言或场景时，本步骤内按固定顺序自动调用：先 Playwright；仅当 Playwright 不可用时再调 Cursor 内置 Browser。不要求用户再次说明或召唤；记录实际用的工具、页面结果与截图类证据。
5. 逐条执行其余断言比对和场景验证（接口、DB、Redis、ES、MQ 等），记录命令、实际值和证据。
6. 多任务合并后做集成和回归验证；含页面的回归项同样自动用浏览器工具。
7. 失败项回流给责任角色，写清归属和定位线索；环境或浏览器工具不可用交 `@@DEVOPS` 或写阻塞原因。
8. 清理测试数据或执行补偿动作，并写清清理方式。
9. 输出质量结论建议，交 `@@TL` 放行判断。
10. 同一失败断言复测 2 轮仍不通过，停止循环交用户决策。

## 输出要求

- 测试计划（含是否启用页面验证；工具结果只能是：已用 Playwright / Playwright 不可用已改用 Browser / 两者皆不可用故阻塞）
- 断言比对（期望值/实际值/证据）
- 场景验证
- 页面验证证据（有页面项时必填）
- 失败项与归属
- 清理方式
- 未覆盖项
- 质量结论建议（通过/阻塞）
