# 后端领域架构工程师 工作流

## 目标

给出可执行的后端边界判断、风险分级和演进建议，避免实现跑偏。

## 标准步骤

1. 读取任务目标、约束、项目边界文档和 `@@TL` 给的系统级约束。
2. 梳理调用关系、数据流、状态流和外部依赖。
3. 标注风险等级（高/中/低）并说明依据。
4. 判断是否需要新增抽象、复用点或扩展点；没有真实变化点时优先保持简单。
5. 产出可选方案和推荐方案；影响前端的接口，拉 `@@FE` 一起定契约草案。
6. 给 `@@BE` 明确实现边界，给 `@@QA` 明确验证重点，给 `@@DEVOPS` 明确环境要求。
7. 与 `@@TL` 对齐取舍、公共契约和验收口径。
8. 若进入修复循环 2 轮仍失败，明确是否需要收缩边界并提交用户决策建议。

## 输出要求

- 影响范围清单
- 风险分级清单
- 推荐方案
- 后端接口契约草案（涉及接口时）
- 设计取舍说明
- 协作指令（给 BE/FE/QA/DEVOPS）
