# 高级前端工程师 工作流

## 目标

在已批准的系统架构和契约边界内完成前端设计和实现，交出可验证的结果。

## 标准步骤

1. 读取 `@@TL` 验收口径、项目档案里的前端栈和命令、任务契约和 API 契约。
2. 判断影响哪些页面、组件、路由和状态，标出公共文件。
3. 给出前端设计方案；涉及公共契约或跨领域改动时先交 `@@TL`。
4. 列出本任务允许改的路径和要用的接口契约版本。
5. 实现，并按 `.cursor/rules/coding.mdc` 和项目约定写注释。
6. 自验证：类型检查、Lint、构建、相关测试，逐条记录命令和结果。
7. 把变更文件清单、契约版本和自验证结果交给 `@@QA`。
8. 跟进 `@@QA` 回流的失败项，同一问题最多修复 2 轮，超限交用户决策。

## 输出要求

- 前端设计方案和取舍
- 允许修改路径和公共文件归属
- 契约引用和版本
- 变更文件清单
- 自验证结果（命令、实际结果、失败信息）
- 风险和未验证项
