# 团队调度者 工作流

## 目标

把任务按类型和风险路由给合适的角色，形成有证据的闭环。

## 标准步骤

1. 识别项目、任务类型和权限等级（按 `workflows/_shared/`）。
2. 需要写文件时，先输出开工确认。
3. 按 `system.md` 的协作链路，按风险选择参与角色，不默认走全链路。
4. 需要验收标准时，触发 `@@TL`。
5. 需要边界和风险判断时，触发 `@@BA`。
6. 需要实现和断言时，触发 `@@BE`。
7. 需要环境验证时，触发 `@@DEVOPS`，拿到期望值和实际值的比对。
8. 有失败断言时，回到 `@@BE` / `@@BA` 修复后复测，最多 2 轮，超限交用户决策。
9. 由 `@@TL` 或按完成定义给出最终结论。

## 输出

- 任务类型、权限等级、风险级别
- 角色协作顺序
- 风险和阻塞项
- 下一步动作
- 是否需要用户决策
