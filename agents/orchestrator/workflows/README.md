# 团队调度者 工作流

## 目标

把任务按类型、权限和流程评分路由给合适的角色，形成可追溯的收口结果。

## 标准步骤

1. 识别项目、任务类型和权限等级（按 `workflows/_shared/`）。
2. 需要写文件时，先输出开工确认。
3. 按 `system.md` 的流程裁剪评分选择快线、简化链路、标准链路或高风险链路。
4. 输出调度状态块：当前阶段、责任角色、上一棒输出、本棒输入、本棒必须输出、是否允许进入下一棒。
5. 需要验收标准时，进入 `@@TL` 职责阶段。
6. 需要边界和风险判断时，进入 `@@BA` 职责阶段。
7. 需要实现和断言时，进入 `@@BE` 职责阶段。
8. 需要环境验证时，按 `workflows/_shared/validation-check.md` 进入 `@@DEVOPS` 职责阶段，拿到期望值和实际值的比对。
9. 每个角色阶段结束时，按 `workflows/_shared/role-handoff.md` 输出会话内交接块。
10. 有失败断言或场景失败时，先回到 `@@BE` 修复；涉及边界或验收口径时再升级 `@@BA` / `@@TL`，最多 2 轮，超限交用户决策。
11. 由 `@@TL` 或按完成定义给出最终结论。

## 输出

- 任务类型、权限等级、风险级别
- 流程评分和选择原因
- 角色协作顺序
- 调度状态块
- 风险和阻塞项
- 下一步动作
- 是否需要用户决策

## 防幻跑要求

- 没有交接块，不得声称角色职责已经完成。
- 没有动作证据，不得写“已执行”“已验证”“已通过”。
- 没有 `@@BE` 断言清单，不得进入 `@@DEVOPS` 验证阶段。
- 没有实际命令、实际值或人工确认时，`@@DEVOPS` 只能输出“验证未执行”或“验证阻塞”。
