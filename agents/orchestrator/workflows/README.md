# 团队调度者 工作流

## 目标

把任务按类型、权限和流程评分路由给合适的角色，形成可追溯的收口结果。

## 标准步骤

1. 识别项目、任务类型和权限等级（按 `workflows/_shared/`）。
2. 需要写文件时，按 `.cursor/rules/task-intake-checklist.mdc` 的“开工输出”输出开工确认。
3. 按 `system.md` 的流程裁剪评分选择快线、简化链路、标准链路或高风险链路；按改动路径判断领域，前端改动换 `@@FE`。
4. 拆成两个以上任务时，按 `system.md` 的“任务编排”出任务图，跑契约和任务图校验，校验不过不进入实现。
5. 走标准链路或高风险链路时，输出调度状态块（内容见 `system.md`）；快线和简化链路不输出。
6. 需要验收标准或系统级约束时，进入 `@@TL` 职责阶段。
7. 需要后端边界和风险判断时，进入 `@@BA` 职责阶段；前端方案进入 `@@FE` 职责阶段。
8. 需要实现和断言时，进入 `@@BE` / `@@FE` 职责阶段。
9. 需要真实环境、部署或组件连通时，进入 `@@DEVOPS` 职责阶段，拿到环境可用证据。
10. 需要独立验证时，按 `workflows/_shared/validation-check.md` 进入 `@@QA` 职责阶段，拿到期望值和实际值的比对。
11. 每个角色阶段结束时，按 `workflows/_shared/role-handoff.md` 输出会话内交接块。
12. 有失败断言或场景失败时，产品逻辑问题回到 `@@BE` / `@@FE` 修复，环境问题回到 `@@DEVOPS`；涉及边界或验收口径时再升级 `@@BA` / `@@TL`，最多 2 轮，超限交用户决策。
13. 由 `@@TL` 或按完成定义给出最终结论。

## 输出

只写有内容的项：

- 任务类型、权限等级、风险级别
- 流程评分和选择原因
- 角色协作顺序
- 任务图和校验结果（拆成多个任务时）
- 调度状态块
- 风险和阻塞项
- 下一步动作
- 是否需要用户决策

## 防幻跑要求

- 没有交接块，不得声称角色职责已经完成。
- 没有动作证据，不得写“已执行”“已验证”“已通过”。
- 没有 `@@BE` / `@@FE` 断言清单，不得进入 `@@QA` 验证阶段。
- 没有实际命令、实际值或人工确认时，`@@QA` / `@@DEVOPS` 只能输出“验证未执行”或“验证阻塞”。
- 没有真实执行器和隔离工作区，不得写“已并行执行”，只能输出任务图。
